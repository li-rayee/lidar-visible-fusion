本项目围绕 **GO2W 四足机器人**搭载的 40 线激光雷达（LiDAR）与前置可见光相机，
设计并实现了一套**全离线**的多传感器协同感知流水线：从 ROS2 Bag 原始数据出发，
完成解析 → 时间同步 → 点云增密 → 坐标归一化与着色 → 三分屏可视化 → H.264 视频合成，
最终以「左视频 / 右俯视 + 侧视」的布局，实现点云与光学视频在空间语义层面的相互印证。

## 1. 项目背景

随着具身智能发展，四足机器人在非结构化环境下的感知能力成为研究热点：

- **LiDAR**：高精度三维测距（本项目 40 线，最大 200m，点频 ≈ 1.152 Mpts/s）
- **可见光相机**：丰富语义纹理（1280×720，≈ 14.3 fps）

二者**互补融合（协同感知）**是机器人精确环境理解的关键路径。本项目的实验平台为深圳大学
实验室 GO2W 四足机器人，采集于 2026-06-10 校园巡检场景，共两段有效 ROS2 Bag
（`bag_094554` ≈ 19s、`bag_102458` ≈ 187s）。

### 核心需求
1. **数据解析**：从 ROS2 Bag 准确提取点云帧（`sensor_msgs/PointCloud2`）与视频帧，处理各自时间戳
2. **时间同步**：两路采样频率不同（LiDAR ≈ 5Hz / 相机 ≈ 14fps），需建立帧级跨传感器时间对齐
3. **场景重建**：单帧仅 ≈ 2000–4000 点，需点云增密方案才能分辨场景结构
4. **可视化输出**：直观呈现「点云与视频相互印证」

### 技术挑战
- 相机标定缺失（无内外参），限制精确重投影，但不影响空间拓扑层面的协同感知
- 时间戳异步（两时钟存在系统偏移与抖动）→ 基于最小绝对差构建帧级对齐
- 点云稀疏（远端密度骤降）→ 设计滑动窗口累积方案

## 2. 系统架构

全离线批处理架构，Python 3.13 开发，核心依赖 `NumPy / Pillow / imageio`。
CPU 串行，单帧渲染 ≈ 0.1s。

```
ROS2 Bag (.db3)
   │
   ├─[1] 数据解析模块──► PointCloud2 解包(struct.unpack) + 视频帧提取(imageio)
   │        │
   ├─[2] 时间同步模块──► LiDAR 帧 ↔ 最近邻视频帧 (bisect, O(N·logM)) → meta.json
   │        │
   ├─[3] 点云处理模块──► 滑动窗口多帧累积(±13帧→≈6万点) + 地面滤除 + 坐标归一化 + 高度/turbo 着色
   │        │
   └─[4] 可视化渲染模块─► 三分屏 Canvas(视频 + 俯视(XY) + 侧视(XZ)) + 方向标注
            │
         [5] 视频合成 ──► imageio-ffmpeg → H.264 MP4
```

| 模块 | 主要功能 | 核心技术 |
|---|---|---|
| 数据解析 | ROS2 Bag 读取、PointCloud2 解包、视频帧提取 | `struct.unpack`、`ffmpeg/imageio` |
| 时间同步 | 构建 LiDAR 帧与视频帧最近邻时间戳映射 | 最小绝对差匹配、`JSON` meta 存储 |
| 点云处理 | 多帧累积、地面滤除、坐标归一化、高度/强度着色 | NumPy 向量化、滑动窗口 |
| 可视化渲染 | 三分屏 Canvas 合成、方向标注 | `Pillow PIL`、`ImageDraw` |
| 视频合成 | 帧序列 → H.264 MP4 编码 | `imageio-ffmpeg` |

## 3. 关键技术

### 3.1 ROS2 Bag 点云解析
ROS2 Bag 以 SQLite3 存储消息（`topic / timestamp / CDR 二进制`）。`PointCloud2` 的 `data`
按字段描述符依次存 `x, y, z, intensity, ring, time`（每点 32 字节），用 `struct.unpack_from`
按 `point_step` 批量提取 `x/y/z/intensity`，保存为 `float32 .bin`。

### 3.2 时间戳同步（最近邻）
为每个 LiDAR 帧找时间上最近的视频帧。视频帧时间戳存有序列表，用 `bisect.bisect_left`
二分查找 + 左右比较取绝对差最小者，复杂度 **O(N·logM)**（N<300, M<3000，离线足够）。

### 3.3 多帧点云累积
低速巡检时单帧仅 2000–4000 点。以当前帧为中心向前后各扩展 **±13 帧**（共 27 帧）拼接，
随机子采样限制总量 ≤ 60000 点，理论获得约 6 万点稠密表示（`bag_094554` 中 95.9% 帧达满）。

### 3.4 坐标归一化与着色
- 去地面（`z < 0.05m`）；`z` 线性映射到 `[0,1]` 经 **turbo LUT** 转高度伪彩（暖色=高处障碍）
- 俯视图（XY 平面）：`+X 前进 → 图上`、`+Y 左 → 图左`，与相机视野严格对应
- 侧视图（XZ 平面）：展示纵断面与障碍物高度分布

### 3.5 三分屏渲染
单帧输出 `1920×720` PNG：左 `854×720` 视频帧、右上 `1066×360` 俯视图、右下 `1066×360`
侧视图，右下角红/绿双箭头标注 X/Y 方向。

## 4. 实验结果

### 4.1 数据集
| 数据包 | 时长(s) | LiDAR帧 | 视频帧 | LiDAR帧率(Hz) | 视频帧率(fps) |
|---|---|---|---|---|---|
| 20260610_094554 | 18.81 | 97 | 245 | 5.16 | 14.3 |
| 20260610_102458 | 187.13 | 143 | 2661 | 0.76 | 14.2 |

### 4.2 时间同步质量（|Δt|）
| 数据包 | 均值(ms) | 中位(ms) | 最大(ms) | <5ms 占比 |
|---|---|---|---|---|
| 20260610_094554 | 15.67 | **0.00** | 46.96 | 23.7% |
| 20260610_102458 | 16.77 | 16.50 | 41.03 | 21.0% |

中位误差 0–17ms，远小于单帧间隔（≈ 65ms@15.3Hz），满足低速同步需求。

### 4.3 点云密度（累积前后）
| 数据包 | 满帧比例 | 点数均值 | 点数最小 | Z 轴范围(m) |
|---|---|---|---|---|
| 20260610_094554 | 95.9% (93/97) | 59,251 | 23,993 | 0.057 ~ 1.047 |
| 20260610_102458 | 28.0% (40/143) | 59,164 | 13,926 | 0.058 ~ 1.541 |

单帧 ≈ 2800 点 → 累积后 ≈ 6 万点，**密度提升约 21 倍**。

### 4.4 可视化结论
① 道路两侧边界在俯视图呈对称点云；② 正前方行人时 `+X` 前端出现局部密集区；
③ 侧视图地面点形成连续条带（z≈0.06m），障碍物在地面线上方竖向突出，与视频高度信息相互印证。

## 5. 运行本仓库的演示

仓库附带**合成数据演示**（`src/demo.py`），无需 137MB 原始视频即可跑通完整流水线并
生成一张三分屏示例图：

```bash
pip install -r requirements.txt
python src/demo.py            # 生成 example_tri_screen.png
```

演示用 NumPy 合成「地面 + 正前方行人 + 两侧建筑立面」点云与一张示意视频帧，
依次经过同步 → 累积 → 渲染，输出与本报告图1–3 同构的三分屏 PNG。

> 真实处理脚本需读取 ROS2 Bag 与 `imageio-ffmpeg`，核心逻辑与 PDF 报告片段一致，
> 见 `src/` 下各模块：`bag_parse.py / sync.py / accumulate.py / render.py`。

## 6. 结论与展望

完整实现了从 ROS2 原始数据到高质量同步可视化视频的全流程离线系统。改进方向：
1. 获取相机标定（内参 K / 外参 R,T），实现点云精确投影叠加到像素平面
2. 引入运动估计（IMU/里程计），累积时加坐标变换消除「拖影」
3. 开发在线实时处理版本
4. 将可视化数据用于训练跨模态感知网络，提升自主导航能力
